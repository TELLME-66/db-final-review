本章把"表"讲成一门可以计算的学问：先用域与笛卡尔积给关系下集合论定义，再区分关系模式（型）与关系（值），然后立起实体完整性、参照完整性、用户定义完整性三条规矩，最后把查询写成关系代数表达式。它是第 3 章 SQL 的地基，也是期末卷上关系代数大题的必考章——除运算与"全部/所有"类查询几乎年年出现，也是最容易失分的地方。

2.1.1关系：域、笛卡尔积与二维表

关系模型只有一种数据结构——关系，用户看到的逻辑结构就是一张二维表。说清它要搭三级台阶：域 → 笛卡尔积 → 关系。

域（Domain）是一组具有相同数据类型的值的集合，域中值的个数称为基数 m，它规定属性的取值范围：D1=｛李力，王平，刘伟｝（m1=3）可表示姓名，D2=｛男，女｝（m2=2）表示性别。

笛卡尔积：给定一组域 D1，D2，…，Dn（允许有相同的域），D1×D2×…×Dn =｛(d1，d2，…，dn) | di∈Di，i=1，…，n｝。每个元素是一个n 元组，元组中的每个 di 是一个分量。若 Di 的基数为 mi，则笛卡尔积的基数 M = ∏(i=1…n) mi。画成二维表时每行一个元组、每列一个域；D1=｛张清玫，刘逸｝、D2=｛计算机专业，信息专业｝、D3=｛李勇，刘晨，王敏｝的笛卡尔积共 2×2×3=12 个元组。

关系是笛卡尔积的有意义的子集，记作 R(D1，D2，…，Dn)。n 称为关系的目或度；n=1 为单元关系，n=2 为二元关系。关系也是二维表，每列必须起名，称为属性，n 目关系必有 n 个属性；不同列可出自同一域，但属性名不能相同。现实中的笛卡尔积大多无意义（"丈夫×妻子×孩子"会配出大量不存在的家庭），所以只取有意义的子集才构成关系。

考点 · 必背

关系数据结构的三个层次与两个基数：

  • 域：同类型值的集合，值的个数为基数 m。
  • 笛卡尔积：所有域取值的一切组合，基数 M = m1×m2×…×mn，不能重复。
  • 关系：笛卡尔积的子集，元组数 ≤ M；目（度）= 属性个数 = 列数。
  • 元组 t、分量 t[Ai]、属性列 A、元组连接 tr ts 是关系代数的记号基础。

考点 · 必背

码的四个概念必须能互相推出：

  • 候选码：能唯一标识元组、且其真子集不能标识的属性组（最小性）。
  • 全码：关系模式的所有属性组成本模式的候选码，是最极端的情形。
  • 主码：多个候选码中选定的那一个，一个关系只有一个主码。
  • 主属性：包含在任一候选码中的属性；否则为非主属性（非码属性）。
关系术语二维表术语要点
关系表一个关系就是一张表
元组行表中一条记录，通常记为 t
属性列必须有属性名，n 目关系 n 个属性
分量单元格必须是原子值，不可再分
候选码能唯一确定行的最小列组可以有多个

基本关系六条性质（判断题高频）：① 列是同质的，同一列来自相同的域；② 不同列可出自同一域，但要有不同属性名；③ 列序无影响；④ 行序无影响；⑤ 任意两个元组的候选码不能相同；⑥ 分量必须取原子值，这是规范化条件中最基本的一条。

易错

（学号，课程号，课程名）不是选课关系的候选码。候选码要求"其子集不能标识"，而（学号，课程号）已能唯一标识元组，所以三元组只是超码。判断候选码只做两件事：先看能否唯一标识，再看是否最小。同理，"全码"不是"把所有属性都拿来当码"，而是客观上不得不全部用上。

例题

（补充例题）设 D1=｛a，b，c｝，D2=｛0，1｝，D3=｛x，y，z，w｝，求 D1×D2×D3 的基数；在它上面定义关系 R，R 最多、最少各有多少元组？

基数 M=3×2×4=24，即共 24 个三元组。关系是笛卡尔积的子集，故 R 最多 24 个元组，最少 0 个（空关系也是关系）。考场上常把"关系元组数"直接写成 24，忘了"子集"二字。

口诀：域定范围，积作全配；子集成关系，码取最小——域规定取值范围，笛卡尔积穷举组合，关系只取有意义的子集，候选码必须最小。

2.1.2关系模式：型与值

关系模式（Relation Schema）是对关系的描述，是型；关系是某一时刻的值。它要描述元组集合的结构（哪些属性、每个属性来自哪个域、属性与域的映像）以及完整性约束条件。

形式化定义为四元组 R(U，D，DOM，F)：R 为关系名；U 为属性名集合；D 为 U 中属性所来自的域；DOM 为属性向域的映像集合；F 为属性间数据依赖关系的集合。笛卡尔积不满足交换律，元组本有位置有序性，关系模型靠给每列增加属性名取消列序，于是 (d1，…，di，dj，…，dn) 与交换后的元组视为同一个。所以常简记为 R(U) 或 R(A1，…，An)，域和映像往往直接写成属性的类型、长度。

DOM 在同一域被多个属性使用时最明显：导师与研究生都取自域 PERSON，则 DOM(SUPERVISOR)=DOM(POSTGRADUATE)=PERSON，两个属性不同名、同域。

考点 · 必背

关系模式与关系的区别（简答题原题）：

  • 关系模式是型，是对关系的描述，静态、稳定；
  • 关系是值，是模式在某一时刻的状态或内容，动态、随时间变化；
  • 关系模式由 R(U，D，DOM，F) 四元组刻画，核心是 U 与 F；
  • 二者常被笼统称为"关系"，要靠上下文区分。

易错

"一个关系模式对应一张固定的表"是错的：模式稳定，表中的行却随插入、删除、修改不断变化。另一处：F 是属性间的数据依赖（如 Sno→Sname），不是完整性约束，二者不要混为一谈。

例题

（补充例题）写出学生关系模式 S(Sno，Sname，Ssex，Sage，Sdept) 的四元组表示，并指出 DOM 与 F 的含义。

R=S；U=｛Sno，Sname，Ssex，Sage，Sdept｝；D=｛学号域，姓名域，性别域，年龄域，系名域｝；DOM(Ssex)=｛男，女｝，DOM(Sage)=整数；F=｛Sno→Sname，Sno→Ssex，Sno→Sage，Sno→Sdept｝。只写 S(Sno，…，Sdept) 是简记形式，不是完整四元组。

2.1.3关系数据库与关系模型的存储结构

一个应用领域中所有关系的集合构成关系数据库。它同样分型与值：型是关系数据库模式（所有关系模式的集合），值是某一时刻这些关系的集合。

存储结构分两个层次：实体与联系都用 Table 表示，但 Table 只是逻辑模型，不是物理存储单位。物理组织由 DBMS 决定：有的系统（如 FoxPro）一个表对应一个操作系统文件，交给操作系统管理；有的大型 DBMS 申请若干大文件，自己划分空间、组织表与索引并统一管理。

易错

"关系数据库的数据都存放在表中"只对基本表成立。视图表是虚表，数据库只保存视图定义、不保存视图数据；查询表更是临时结果。三者混为一谈是判断题的送分点。

本节小结

  • 域 → 笛卡尔积（基数 ∏mi）→ 关系（有意义的子集），目 = 属性数。
  • 码体系：候选码（最小、可多个）→ 主码（选定一个）→ 主属性 / 非主属性；极端情形是全码。
  • 基本关系六性质：列同质、异列可同域、列序无关、行序无关、候选码不重复、分量原子。
  • 关系模式 R(U，D，DOM，F) 是型，关系是值；关系数据库的型是模式集合，值是关系集合。
  • 表是逻辑结构，物理组织由 DBMS 决定；视图表不存数据。

2.2关系操作与关系数据语言

关系操作分查询与更新：查询有选择、投影、连接、除、并、交、差、笛卡尔积；更新有插入、删除、修改。查询的表达能力是其中最主要的部分。

关系操作的特点是集合操作方式（set-at-a-time）：操作对象和结果都是集合；层次、网状模型是 record-at-a-time（一次一记录）。

五种基本操作是选择、投影、并、差、笛卡尔积。交、连接、除均可由这五种导出，引进它们不增加语言能力，只简化表达。关系代数表达式就是这些运算经有限次复合得到的式子。

考点 · 必背

五个基本运算与三个导出运算：

  • 基本：σ（选择）、π（投影）、∪（并）、−（差）、×（笛卡尔积）。
  • 导出：R∩S = R−(R−S) = S−(S−R)；R⋈S = π属性表(σ公共属性相等(R×S))；R÷S = πX(R) − πX(πX(R)×πY(S) − R)。
  • 传统集合运算从行的角度进行；专门的关系运算不仅涉及行而且涉及列。

关系数据语言分三类：关系代数语言（对关系的运算，代表 ISBL）；关系演算语言（用谓词，元组演算代表 ALPHA、QUEL，域演算代表 QBE）；双重特点的 SQL。三者表达能力完全等价；关系语言高度非过程化，存取路径由 DBMS 优化机制选择。

用三种语言表达"查询计算机系的学生姓名"（课件原例）。

关系代数：πSname(σSdept='CS'(Student))。
元组演算：｛t[Sname] | t∈Student ∧ t[Sdept]='CS'｝。

① 交、连接、除不是基本运算。② 三种语言"表达能力等价"，不是"关系演算更强"；SQL 是双重特点语言，既非纯代数也非纯演算。③ "一次一记录"是层次/网状模型的特征，不是关系模型。

2.3.1实体完整性

规则 2.1（实体完整性）：若属性 A 是基本关系 R 的主属性，则 A 不能取空值。空值表示"不知道/不存在/无意义"，不是确定取值，不能承担标识实体的任务。

理解要抓四点：① 规则针对基本关系，一个基本表通常对应现实世界的一个实体集；② 现实中的实体可区分，具有唯一性标识；③ 关系模型以主码作唯一性标识；④ 主属性取空值就会出现不可标识、不可区分的实体，与②矛盾，规则因此得名。实现上由 DBMS 自动检查主码非空且唯一，违约拒绝；"非空"与"唯一"是两条检查，缺一不可。

考点 · 必背

实体完整性三句话：

  • 规则：主属性不能取空值（主码非空且唯一）。
  • 理由：实体必须可区分，主码是唯一标识，主码为空 = 存在不可标识的实体。
  • 实现：DBMS 自动检查，违约拒绝；只对基本表提要求，视图不受此约束。

例题

学生（学号，姓名，性别，系名）已有 0101、0102、0203 三行。下列能否插入？A.('0203'，'张'，男，null)　B.(null，'吴'，女，'IS')　C.('0301'，null，null，null)　D.('0105'，'张'，男，'MA')

A 不能：主码 0203 已存在。B 不能：主码为 null。C 能：主码 0301 非空且不重复，其它属性为空不违反实体完整性（若无非空约束）。D 能：主码 0105 非空且不重复。
判断顺序：主码是否为空 → 是否重复 → 其它约束。

易错

实体完整性只管主属性。非主属性（姓名、性别、系名）可以为空，除非另有用户定义的非空约束——把"所有属性都不能为空"当成实体完整性是典型错误。一个表可有多个候选码，但只能有一个主码。

2.3.2参照完整性

实体与实体间的联系都用关系描述，于是出现关系间的引用。【例 2.1】学生（学号，姓名，性别，专业号，年龄）引用专业（专业号，专业名）的主码；【例 2.2】选修（学号，课程号，成绩）的"学号"引用学生、"课程号"引用课程；【例 2.3】学生（…，班长）的"班长"引用本关系的学号——同一关系内部也能引用。

外码：设 F 是基本关系 R 的一个或一组属性，但不是 R 的码；若 F 与基本关系 S 的主码 Ks 相对应，则 F 是 R 的外码。R 称参照关系，S 称被参照关系。四个要点：R 与 S 可同一；Ks 与 F 必须同域；外码不必与主码同名；外码取值由规则 2.2 约束。

规则 2.2（参照完整性）：R 中每个元组在 F 上的值必须或者取空值（F 的每个属性均为空），或者等于 S 中某个元组的主码值，二者必居其一。对照三例："专业号"只能取空值（未分配专业）或专业表中确实存在的主码值；选修的"学号""课程号"是主属性，不能为空，只能取已存在的主码值；"班长"可为空，非空时必须是本关系中某元组的学号。

违约处理（补充，SQL 标准三策略）：删除或修改被参照表的主码值而仍有外码引用时，DBMS 按预先声明的策略处理，否则引用就断了。

  1. 拒绝（NO ACTION / RESTRICT）：有引用就拒绝删除或修改，语句报错回滚。最安全，常为默认策略。
  2. 级联（CASCADE）：删除被参照元组时连带删除引用它的元组；修改主码时把外码值一起改。引用始终一致，但可能连锁删除。
  3. 置空（SET NULL）：把引用元组的外码置为 NULL。要求该外码可空且不是参照表主码的组成部分，否则会违反实体完整性。
策略删除被参照元组时修改被参照主码时适用条件与风险
拒绝 NO ACTION / RESTRICT有引用则拒绝删除有引用则拒绝修改任何情况可用；最安全，需先手工清理
级联 CASCADE连带删除参照元组连带修改外码值引用必须一致时用；有连锁删除风险
置空 SET NULL把外码置为 NULL把外码置为 NULL外码可空且非主属性；会丢失引用信息

考点 · 必背

参照完整性答题模板：

  • 先指外码：F 不是 R 的码，却与 S 的主码 Ks 对应；R 是参照关系，S 是被参照关系。
  • 再写规则：F 取空值或等于 S 中某元组的主码值。
  • 最后写违约处理：拒绝、级联、置空，并说明置空要求外码可空且非主属性。

例题

供应商 S（主码：供应商号）已有 B01、S10、T20、Z01；零件 P（主码：零件号，外码：供应商号）已有 010、312、201。下列 P 的行能否插入？A.('037'，'绿'，null)　B.(null，'黄'，'T20')　C.('201'，'红'，'T20')　D.('105'，'蓝'，'B01')　E.('101'，'黄'，'T11')

A 能：零件号新，供应商号为空，参照完整性允许。B 不能：主码为 null，违反实体完整性。C 不能：主码 201 重复。D 能：零件号新，B01 存在。E 不能：T11 不存在，违反参照完整性。
判断顺序：实体完整性 → 参照完整性 → 用户定义完整性。

易错

"外码一定可以取空值"是错的。若 F 恰是参照关系的主属性（如【例 2.2】的学号、课程号），它同时受实体完整性约束，不能为空，只能取被参照表中已存在的主码值——这是两条规则叠加的高频判断。另一处：外码与主码不要求同名，只要求同域。

口诀：外码"空或有"，删除"拒级空"——外码取值要么为空、要么等于被参照表某个主码值；违约处理是拒绝、级联、置空。

2.3.3用户定义的完整性

用户定义的完整性是针对某一具体数据库的约束，反映具体应用的语义要求。课件例子：课程号唯一；非主属性课程名也不能为空；学分只能取｛1，2，3，4｝；成绩在 0～100；学号为 8 位整数；性别取"男"或"女"；年龄在 15～25。

分工是：实体完整性、参照完整性是关系模型必须满足的条件，称关系的两个不变性，系统必须自动支持；用户定义完整性体现领域语义，由用户定义后交系统支持。实现方式是 DBMS 提供定义接口（UNIQUE、NOT NULL、CHECK、DEFAULT 等，第 5 章展开），在插入、修改时自动检查，违约拒绝。

完整性约束对象规则违约处理是否自动支持
实体完整性基本表的主属性主码非空且唯一拒绝关系系统必须自动支持
参照完整性外码取空值或等于被参照表某主码值拒绝 / 级联 / 置空大型系统能自动支持
用户定义完整性具体应用的属性由语义定，如 CHECK、UNIQUE、NOT NULL拒绝用户定义后由系统检查

例题

学生表要求 GPA 不超过 4.0。现插入 (124，John，4.5，20)，能否成功？

不能。GPA=4.5 超过上限 4.0，违反用户定义完整性，DBMS 检查后拒绝插入。注意主码 124 非空且不重复，所以不是实体完整性问题；也没有引用其它表，不是参照完整性问题。答题必须点明"违反的是用户定义完整性的取值范围约束"。

易错

用户定义完整性不是"由应用程序自己检查"，也不是"用户想定就定、系统不管"。正确表述：用户通过 DBMS 提供的手段定义，DBMS 在更新时自动检查并拒绝违约操作。加在非主属性上的唯一性约束（如课程名）属于用户定义完整性，不要答成实体完整性。

本节小结

  • 实体完整性：主属性不能取空值，主码非空且唯一；DBMS 自动检查，违约拒绝。
  • 参照完整性：外码取空值或等于被参照表某主码值；违约可拒绝、级联、置空。
  • 用户定义完整性：反映具体语义（范围、格式、非空、唯一），用户定义、系统检查。
  • 前两者合称两个不变性；三类完整性的实现机制统一为"定义接口 + 自动检查 + 违约拒绝"。

2.4.1传统的集合运算

传统集合运算是二目运算，从行的角度进行。除笛卡尔积外，都要求两个关系相容：① 同度；② R 的第 i 个属性与 S 的第 i 个属性来自同一个域。

并 R∪S：n 目，属于 R 或属于 S 的元组，重复只留一个。差 R−S：属于 R 而不属于 S 的元组，方向不可交换。交 R∩S：既属于 R 又属于 S，且 R∩S = R−(R−S) = S−(S−R)。笛卡尔积 R×S：R 为 n 目 k1 个元组、S 为 m 目 k2 个元组，结果为 n+m 列、k1×k2 行；它不要求相容，作用是把两个关系无条件拼成新关系，供连接使用。

R ∪ S = { t | t∈R ∨ t∈S }
R − S = { t | t∈R ∧ t∉S }
R ∩ S = { t | t∈R ∧ t∈S } = R−(R−S) = S−(S−R)
R × S = { tr ts | tr∈R ∧ ts∈S }
运算结果度结果元组数是否要求相容
R∪Sn≤ m+n，重复元组只留一份是（同度、对应列同域）
R−Sn≤ m是
R∩Sn≤ min(m，n)是
R×Sn+mk1×k2否

例题

R=｛(a1，b1，c1)，(a1，b2，c2)，(a2，b2，c1)｝，S=｛(a1，b2，c2)，(a1，b3，c2)，(a2，b2，c1)｝，求 R∪S、R−S、R∩S。

R∪S=｛(a1，b1，c1)，(a1，b2，c2)，(a2，b2，c1)，(a1，b3，c2)｝，共 4 个元组（两个重复只留一份）。
R−S=｛(a1，b1，c1)｝。
R∩S=｛(a1，b2，c2)，(a2，b2，c1)｝。
验算：R−S 与 R∩S 合起来恰是 R，且二者不相交。

口诀：并去重、差单向、交取共、积全配——并集去掉重复，差有方向，交取公共元组，笛卡尔积两两配对。

易错

① 并、差、交要求相容，笛卡尔积不要求。② 并、差、交结果都是 n 度，只有笛卡尔积是 n+m 列。③ R−S ≠ S−R。④ 关系是集合，并运算自动去重，保留重复元组就错。

2.4.2专门的关系运算（一）：选择、投影与连接

选择 σF(R) =｛t | t∈R ∧ F(t)='真'｝：F 由比较运算符（＞、≥、＜、≤、＝、<>）和逻辑运算符（¬、∧、∨）组成，基本形式 XθY，X、Y 可为属性名、列序号、常量或简单函数。选择从行的角度运算，是水平分割，度不变。例2.4 查 IS 系学生：σSdept='IS'(Student)；例2.5 查年龄小于 20 岁：σSage<20(Student)，也可写 σ[4]<20(Student)。

投影 πA(R) =｛t[A] | t∈R｝：从列的角度运算。投影后不仅取消某些列，还可能取消某些元组——关系不允许重复元组，重复行必须去掉；列可重排。例2.6：πSname,Sdept(Student)；例2.7 查有哪些系：πSdept(Student)，4 个学生只得到 3 个系。

θ 连接：R⋈AθBS = σR[A]θS[B](R×S)，A、B 是度数相等且可比的属性组，θ 为比较运算符，即"笛卡尔积＋选择"。等值连接是 θ 取"＝"，两份重复属性都保留。自然连接是特殊的等值连接：比较的必须是相同的公共属性组，并在结果中去掉重复的属性列，设公共属性集为 B、全体属性为 U，则 R⋈S =｛tr ts[U−B] | tr∈R ∧ ts∈S ∧ tr[B]=ts[B]｝。θ 连接只看行，自然连接同时看行和列。

用基本运算表达：R(A，B，C) 与 S(C，D) 时 R⋈S = π1,2,3,5(σ[3]=[4](R×S))；一般地 R⋈S = πAttr(R)∪Attr(S)(σR.A1=S.A1 ∧ … ∧ R.An=S.An(R×S))。若两关系无公共属性，则 R⋈S = R×S：等值条件恒真、无重复列可去，自然连接退化为笛卡尔积，而不是空集。

悬浮元组：自然连接时在对方找不到公共属性相等的元组，被舍弃，称悬浮元组。外连接把它保留、其它属性填 NULL：左外连接只保留左关系 R 的悬浮元组，右外连接只保留右关系的。

例题

【例 2.8】R(A，B，C)=｛(a1，b1，5)，(a1，b2，6)，(a2，b3，8)，(a2，b4，12)｝，S(B，E)=｛(b1，3)，(b2，7)，(b3，10)，(b3，2)，(b5，2)｝。求 θ 连接（C<E）、等值连接（R.B=S.B）、自然连接及外连接。

① θ 连接：(a1，b1，5，b2，7)、(a1，b1，5，b3，10)、(a1，b2，6，b2，7)、(a1，b2，6，b3，10)、(a2，b3，8，b3，10)，共 5 行。
② 等值连接：(a1，b1，5，b1，3)、(a1，b2，6，b2，7)、(a2，b3，8，b3，10)、(a2，b3，8，b3，2)，共 4 行，B 列出现两次。
③ 自然连接：在②上去掉重复的 B 列，得 (a1，b1，5，3)、(a1，b2，6，7)、(a2，b3，8，10)、(a2，b3，8，2)。
④ 外连接：悬浮元组 (a2，b4，12) 与 (b5，2) 补成 (a2，b4，12，NULL)、(NULL，b5，NULL，2)；左外只补前者，右外只补后者。

考点 · 必背

连接与投影的四条硬结论：

  • θ 连接 = 笛卡尔积 + 选择：R⋈AθBS = σR[A]θS[B](R×S)。
  • 自然连接 = 等值连接 + 去掉重复列，比较的必须是公共属性组。
  • 无公共属性时 R⋈S = R×S，不是空关系。
  • 投影一定检查去重；选择不改变度，投影可能减少行。

易错

① 自然连接去掉的必须是比较用的公共属性中重复的那一份，非公共属性一列都不能少。② 等值连接保留两份连接列，自然连接只留一份，这是两者唯一区别。③ 悬浮元组是被舍弃的元组，左外连接保留左表的，别写反。④ 用列序号时，R×S 的后 m 列序号从 n+1 起，π 的下标从 1 连续数。

2.4.2专门的关系运算（二）：除运算

除运算表达"全部""所有"这类全称量词（∀）查询：找出与另一关系中每一个元组都能匹配的元组。典型题干："选修了所有课程的学生""购买了所有商品的顾客"。它是本章最容易失分的地方。

象集：给定 R(X，Z)，当 t[X]=x 时，x 在 R 中的象集 Zx =｛t[Z] | t∈R，t[X]=x｝，即固定 X 的某个值后 Z 上所有出现过的分量组合。

除的定义：给定 R(X，Y) 与 S(Y，Z)，R 中的 Y 与 S 中的 Y 可不同名但必须同域。R÷S 得到 P(X)，由 R 中满足"x 的象集 Yx 包含 S 在 Y 上投影集合"的元组在 X 上的投影组成：R÷S =｛tr[X] | tr∈R ∧ πY(S) ⊆ Yx｝。直观含义：x 与 S 中每一个 y 都能在 R 中配上对。结果只有 X 的属性。

按定义硬算容易漏，标准做法是四步算法：

  1. T = πX(R)：R 在 X 上的投影，即所有候选的 x。
  2. W = T × πY(S)：所有"x 与 S 中每个 y"的应有组合。
  3. V = πX(W − R)：W 中 R 里缺失的组合，投影出"有缺口的 x"。
  4. R÷S = T − V：去掉有缺口的 x，剩下的就是与每个 y 都配对的 x。
R ÷ S = πX(R) − πX( πX(R) × πY(S) − R )

例题

【例 2.9】R(A，B，C)=｛(a1，b1，c2)，(a2，b3，c7)，(a3，b4，c6)，(a1，b2，c3)，(a4，b6，c6)，(a2，b2，c3)，(a1，b2，c1)｝，S(B，C，D)=｛(b1，c2，d1)，(b2，c1，d1)，(b2，c3，d2)｝，求 R÷S。

πBC(S)=｛(b1，c2)，(b2，c1)，(b2，c3)｝。
a1 的象集=｛(b1，c2)，(b2，c3)，(b2，c1)｝，包含 πBC(S)，保留；a2 的象集=｛(b3，c7)，(b2，c3)｝、a3 的象集=｛(b4，c6)｝、a4 的象集=｛(b6，c6)｝都缺，舍去。
所以 R÷S=｛a1｝，结果只有 A 一列。
四步验算：T=｛a1，a2，a3，a4｝；W=T×πBC(S) 共 12 行；W−R 中 a2、a3、a4 都有缺失；V=｛a2，a3，a4｝；T−V=｛a1｝。

考点 · 必背

除运算的三条判据：

  • 题干出现"全部、所有、每一门、都"，优先想除；"至少两门"用自连接，"没有选修"用差。
  • 被除关系必须是 R(X，Y)，Y 只能是 S 中用于比较的属性组，多余属性先投影掉。
  • 结果只有 X 的属性；要姓名就再与 Student 自然连接后投影。

易错

把"选修了全部课程的学生"写成 SC ÷ πCno(Course) 是本章第一大错：SC 的属性是 (Sno，Cno，Grade)，Y 必须恰好是 Cno，多出的 Grade 使"象集包含"永远不成立，结果恒为空。正确写法是先投影：πSno,Cno(SC) ÷ πCno(Course)。第二处：除的结果不含 Y，要"学生姓名"必须再连接 Student。第三处：除不满足交换律，R÷S 与 S÷R 完全不同。

口诀：全称先投影，X 除 Y；T、W、V、T−V——先把被除关系投影到 X∪Y，再按"投影、乘、差、再差"四步求商。

考点 · 必背

复杂查询四步套路（大题按这个顺序写，步骤分稳拿）：

  • 定表：涉及哪几个关系，先按主码-外码自然连接。
  • 筛行：把"某系、某课、某年龄"等条件写成 σ，字符串加引号。
  • 取列：题目要什么就 π 什么，多一列少一列都扣分。
  • 判全称："全部/所有"用除；"没有/不"用差；"至少两门"用自连接。

易错

① 关系代数没有聚集函数，"平均成绩""人数""最高分"不能写成 π 或 σ，必须说明用 SQL 的 AVG/COUNT/MAX，这是概念题高频陷阱。② 多表连接后忘投影，或投影时漏掉连接键导致无法再连。③ "没有选修"用差时两侧属性列必须完全一致。④ 字符串用单引号、数字不加引号；列序号按连接后的列序从 1 数。

口诀：先连表、再筛行、后取列；全部用除、没有用差、两门自连——四步套路加三个关键词，综合题不会跑偏。

本节小结

  • 单表查询：σ 管行、π 管列，先选择后投影，投影记得去重。
  • 多表查询：按主码-外码自然连接，再 σ 筛行、π 取列；三表按"学生-选修-课程"顺序写。
  • "全部/所有"用除：被除关系先投影到 X∪Y，结果为 X，要姓名再连接。
  • "至少两门"用自连接；"没有/不"用差，两侧投影列必须相容。
  • 关系代数不含聚集函数，涉及统计必须转 SQL，这是本章与第 3 章的分界。
