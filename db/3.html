3.1SQL 概述：五大特点与三级模式

SQL（Structured Query Language）是关系数据库的标准语言。1974 年 Boyce 和 Chamberlin 提出 SEQUEL，IBM 将其用于 SYSTEM R；1981 年改名 SQL，1982 年美国国家标准局 ANSI 开始制定 SQL 标准。标准版本从 SQL/86、SQL/89、SQL/92 一路膨胀到 SQL99、SQL2003、SQL2008（3777 页）、SQL2011、SQL2016、SQL2019，陆续加入递归查询、触发器、XML/JSON、窗口函数、时态数据等。至今没有一个数据库系统能支持 SQL 标准的全部概念和特性，各厂商都是"标准 + 方言"：Oracle 是 PL/SQL，SQL Server 是 T-SQL。考试若问"SQL 是不是严格的标准语言"，答"是工业标准，但产品只实现其子集并各自扩充"。

考点 · 必背

SQL 的五个特点，简答题按"名称 + 一句解释"给分：

  • 综合统一：集 DDL、DML、DCL 于一体，数据结构单一（只有关系），操作符统一，能独立完成数据库生命周期中的全部活动。
  • 高度非过程化：只说明"做什么"，不指定存取路径，路径由系统自动选择，因而数据独立性高。
  • 面向集合：操作对象和查找结果都是元组的集合，一次插入、删除、更新可以作用于多个元组。
  • 同一种语法结构、两种使用方式：既可独立联机交互，又可嵌入 C/C++/Java 等宿主语言，两种方式语法基本一致。
  • 语言简洁、易学易用：核心功能只用 9 个动词。

9 个动词必须能默写并归类，选择题常拿"哪个不是 SQL 动词"来设套（如 JOIN、INDEX 都不是）。

口诀：一查三定三操纵，二控制——SELECT；CREATE/DROP/ALTER；INSERT/UPDATE/DELETE；GRANT/REVOKE，合计 9 个动词。

SQL 支持关系数据库的三级模式结构，这是"SQL 基本概念"最常考的一张图：视图对应外模式，基本表对应模式，存储文件对应内模式。三者关系要能反过来答：

基本表是本身独立存在的表，一个关系对应一个基本表；一个（或多个）基本表对应一个存储文件，一个表可带若干索引，索引也存放在存储文件中。存储文件的逻辑结构和物理结构组成内模式，物理结构对用户隐蔽、可以任意改变。视图从一个或几个基本表导出，数据库中只存放视图的定义而不存放视图对应的数据，是虚表，且可以在视图上再定义视图。在用户眼中视图和基本表都是关系，存储文件对用户透明。

易错

"SQL 是非过程化语言"不等于"SQL 不能写过程"——SQL 仍可用游标、存储过程描述流程，非过程化指的是不指定存取路径。另一个高频错点是把"两种使用方式"答成"两种语法"：独立式与嵌入式语法结构基本一致，差别只在宿主语言的接口（如共享变量、游标）。

例题

同样的查询"不在武汉居住的供应商"，SQL 写作 SELECT * FROM S WHERE city<>'Wuhan'，而 QUEL 必须写 RANGE OF s IS S 再 RETRIEVE (s.all) WHERE (s.city<>"Wuhan")。这说明了 SQL 的什么特点？

说明高度非过程化：SQL 只描述结果应满足的条件（做什么），不指出用哪个索引、按什么顺序扫描（怎么做）；QUEL 要先用 RANGE 声明元组变量，带有明显的面向过程痕迹。答案要点是"只提做什么、存取路径由系统选择、减轻用户负担、提高数据独立性"。

【例 3.5】【例 3.6】【例 3.7】三张表的建表语句，考试要求原文写出：

CREATE TABLE Student
 (Sno    CHAR(9)  PRIMARY KEY,        -- 列级约束：Sno 是主码
  Sname  CHAR(20) UNIQUE,             -- 姓名取值唯一
  Ssex   CHAR(2),
  Sage   SMALLINT,
  Sdept  CHAR(20),
  CHECK (Ssex = '男' OR Ssex = '女'));

CREATE TABLE Course
 (Cno     CHAR(4)  PRIMARY KEY,
  Cname   CHAR(40),
  Cpno    CHAR(4),
  Ccredit SMALLINT,
  FOREIGN KEY (Cpno) REFERENCES Course(Cno));   -- 自参照外码

CREATE TABLE SC
 (Sno   CHAR(9),
  Cno   CHAR(4),
  Grade SMALLINT,
  PRIMARY KEY (Sno, Cno),              -- 多属性主码必须表级定义
  FOREIGN KEY (Sno) REFERENCES Student(Sno),
  FOREIGN KEY (Cno) REFERENCES Course(Cno),
  CHECK ((Grade IS NULL) OR Grade BETWEEN 0 AND 100));

考点 · 必背

建表语句的采分点只有四处，写全即满分：

  • 列级约束写在列定义后：PRIMARY KEY、UNIQUE、NOT NULL、CHECK、DEFAULT。
  • 表级约束单列一行：PRIMARY KEY(列,…)、FOREIGN KEY(列) REFERENCES 表(列)、CHECK(条件)。凡涉及多个属性列的约束（含复合主码）必须写在表级。
  • 外码的"被参照列"必须是主码或 UNIQUE 列，且类型可比。
  • CHECK 里要放行空值时必须显式写 Grade IS NULL OR …，否则空值会让条件取 UNKNOWN，插入缺考记录可能被拒。

易错

SC 的 Grade 允许为空是有意设计：有选课记录但未考试。这条设定是 3.6 节和【例 3.82】"不及格但不含缺考"的伏笔。若把 Grade 写成 NOT NULL，就与全书例题的数据矛盾。另一个错点是把 SC 的主码写成 Sno 或 Cno 单列——一个学生选多门课、一门课被多人选，只有 (Sno, Cno) 才能唯一标识一条选课记录。

3.3数据定义：模式、基本表、索引与数据字典

SQL 的数据定义靠三条语句：CREATE、DROP、ALTER，作用对象是模式、表、视图、索引。先记层次：一个实例可有多个数据库，一个数据库可有多个模式，一个模式包含多个表、视图、索引。定义模式本质上就是建立一个命名空间，而不是建一个"数据库"。

CREATE SCHEMA <模式名> AUTHORIZATION <用户名> [<表定义子句> | <视图定义子句> | <授权子句>];
DROP   SCHEMA <模式名> <CASCADE | RESTRICT>;

【例 3.1】CREATE SCHEMA "S-T" AUTHORIZATION WANG;。【例 3.2】省略模式名时，模式名隐含为用户名。【例 3.3】在 CREATE SCHEMA 后直接跟 CREATE TABLE，可一次建模式并建表。删除时 CASCADE 表示把模式内所有对象一起删（【例 3.4】DROP SCHEMA ZHANG CASCADE; 连 TAB1 一起删）；RESTRICT 表示模式内还有对象就拒绝删除。凡 CASCADE/RESTRICT 二选一，判断标准只有一句：RESTRICT 要求"没有下属对象"，CASCADE 则"连坐"。

基本表所属模式有三种指定方法：表名前直接加模式名（CREATE TABLE "S-T".Student(…)）、在 CREATE SCHEMA 中同时建表、设置搜索路径后建表。搜索路径用 SHOW SEARCH_PATH; 查看，默认值 $user, PUBLIC，系统取路径中第一个存在的模式；SET SEARCH_PATH TO "S-T", PUBLIC; 之后建的表就属于 S-T。

CREATE TABLE <表名> (
  <列名> <数据类型> [DEFAULT 缺省值] [NOT NULL] [列级约束],
  …
  [, PRIMARY KEY (列名 [, 列名] …)]
  [, FOREIGN KEY (列名 [, 列名] …) REFERENCES 表名 (列名 [, 列名] …)]
  [, CHECK (条件表达式)]);

修改表用 ALTER TABLE：ADD 增列（【例 3.8】ALTER TABLE Student ADD S_entrance DATE;）、ALTER COLUMN 改类型（【例 3.9】Sage 改 INT）、ADD 表级约束（【例 3.10】ALTER TABLE Course ADD UNIQUE(Cname);）、DROP COLUMN、DROP CONSTRAINT。新增加的列不论表里原来有没有数据，一律取空值；若新增列声明 NOT NULL，则必须同时给 DEFAULT，否则语句失败。

删表 DROP TABLE <表名> [RESTRICT|CASCADE];：RESTRICT 要求该表不被其他表的约束、视图、触发器等引用；CASCADE 则把依赖对象一并删掉。【例 3.12】中 Student 上有视图 IS_Student，DROP TABLE Student RESTRICT; 报错，改 CASCADE 后视图自动消失，再查 IS_Student 提示关系不存在。注意：删除视图必须显式 DROP VIEW，删表并不会自动删视图定义之外的依赖管理，标准与各产品处理不同，答题以"RESTRICT 拒绝、CASCADE 连坐"为准。

索引是为了加快查询，把查找从 O(n) 降到 O(log₂n)。常见类型有顺序文件索引、B+ 树索引（动态平衡）、散列索引（查找快）、位图索引。

CREATE [UNIQUE] [CLUSTER] INDEX <索引名>
  ON <表名> (<列名> [ASC|DESC] [, <列名> [ASC|DESC]] …);
ALTER INDEX <旧索引名> RENAME TO <新索引名>;
DROP  INDEX <索引名>;

【例 3.13】CREATE UNIQUE INDEX Stusno ON Student(Sno);、CREATE UNIQUE INDEX Coucno ON Course(Cno);、CREATE UNIQUE INDEX SCno ON SC(Sno ASC, Cno DESC);。【例 3.14】改名为 SCSno。【例 3.15】DROP INDEX Stusname; 删除时系统同步从数据字典删掉该索引的描述。

考点 · 必背

索引的三个"谁"与建索引原则：

  • 谁建：DBA 或表的属主；谁维护：RDBMS 自动完成；谁用：系统自动选择存取路径，用户不必也不能在 SQL 中显式引用索引——这正是物理独立性的体现。
  • 聚簇索引：索引项顺序与表中记录的物理顺序一致，同值记录构成一簇只存一个索引值；查询快，但维护成本高，一个表只能建一个，经常更新的列不宜建。
  • 建索引原则：主码列一定要建；外码列可以建；常作连接属性、常出现在查询条件中的列最好建；很少涉及、重复值多的列不建；text、image、bit 类型不建。
  • 索引不是越多越好：过多索引耗费空间，并降低 INSERT/UPDATE/DELETE 的效率。

易错

UNIQUE 索引保证索引值唯一，但它不等于主码：一个表可有多个 UNIQUE 索引，主码只有一个，且 UNIQUE 列允许空值（见 3.6 节）。另一个错点是把聚簇索引当成"可以建多个"——物理顺序只有一种，"一个表只能一个聚簇索引"是选择题常客。

例题

【例 3.3】为用户 ZHANG 创建模式 TEST，并在其中定义表 TAB1（COL1 SMALLINT、COL2 INT、COL3 CHAR(20)、COL4 NUMERIC(10,3)、COL5 DECIMAL(5,2)），写出语句。

CREATE SCHEMA TEST AUTHORIZATION ZHANG 后紧跟 CREATE TABLE TAB1 (COL1 SMALLINT, COL2 INT, COL3 CHAR(20), COL4 NUMERIC(10,3), COL5 DECIMAL(5,2));。要点：模式名在前、AUTHORIZATION 在后；子句之间不用逗号；NUMERIC(10,3) 表示共 10 位数字、其中小数 3 位，即整数部分最多 7 位。

数据字典是 RDBMS 内部的一组系统表，记录关系模式定义、视图定义、索引定义、完整性约束定义、各类用户的操作权限和统计信息。执行 DDL 语句实际上就是在更新数据字典中的相应信息，这也是"数据字典"必考的一句结论。

3.4.1单表查询：SELECT 的五种武器

查询的骨架来自关系代数 σ、π：SELECT A1,…,An FROM R1,…,Rm WHERE F 对应 πA1…An(σF(R1×…×Rm))。SQL 的 WHERE 条件比关系代数的公式灵活得多，但结果永远是一张表（元组的集合），这一点决定了后面所有"嵌套""集合"写法的合法性。

SELECT 子句能放：列名、*、算术表达式、字符串常量、函数、列别名。【例 3.19】SELECT Sname, 2024-Sage FROM Student; 查出姓名与出生年份。【例 3.20】还可拼常量串、用 LOWER(Sdept) 把系名转小写。别名用空格或 AS 引出：【例 3.20 续】SELECT Sname NAME, 'Year of Birth:' BIRTH, 2024-Sage BIRTHDAY, LOWER(Sdept) DEPARTMENT FROM Student;。

DISTINCT 作用于整个目标列组合，不是某一列；缺省为 ALL，重复行保留。【例 3.21】SELECT Sno FROM SC; 得到 5 行（202215121 出现三次），加 DISTINCT 后只剩 2 行。凡"查询选修了课程的学生学号""选修了某课的学生"一类题，若只选 Sno，必须想清楚要不要 DISTINCT；用了 GROUP BY 或 IN/EXISTS 时通常已天然去重。

查询条件谓词典型例句
比较=、>、<、>=、<=、!=、<>、!>、!<，可加 NOT【例 3.22】WHERE Sdept='CS'；【例 3.24】WHERE Grade<60

LIKE 只有两个通配符：% 代表任意长度（可为 0）的字符串，_ 代表任意单个字符。【例 3.30】姓刘 '刘%'；【例 3.31】姓"欧阳"且全名三个汉字写 '欧阳_'（复姓占两字、全名三字，后面只剩一个字符，故只跟一个下划线；课件该处印成两个下划线，系排版笔误）；【例 3.32】名字第二个字是"阳"写 '__阳%'（前面两个下划线）。若模式串本身含 % 或 _，必须用 ESCAPE 指定换码字符：【例 3.34】查课程名恰为 DB_Design 写作 WHERE Cname LIKE 'DB\_Design' ESCAPE '\'；【例 3.35】以 DB_ 开头且倒数第 3 个字符为 i 写作 WHERE Cname LIKE 'DB\_%i__' ESCAPE '\'。匹配串不含通配符时，LIKE 等价于 =（【例 3.29】）。

排序用 ORDER BY 列 [ASC|DESC]，可多列，缺省 ASC，空值的排序位置由具体系统决定。【例 3.39】按成绩降序；【例 3.40】ORDER BY Sdept, Sage DESC 表示先按系升序、同系内按年龄降序—— ASC/DESC 只作用于紧挨着的那一列。

聚集函数五个：COUNT、SUM、AVG、MAX、MIN，只能出现在 SELECT 子句和 HAVING 子句中。【例 3.41】COUNT(*) 数学生总人数；【例 3.42】COUNT(DISTINCT Sno) 数选修了课程的人数（去重）；【例 3.43】1 号课平均分；【例 3.44】最高分；【例 3.45】某学生总学分要连接 SC 与 Course 后 SUM(Ccredit)。除 COUNT(*) 外，聚集函数都跳过空值只处理非空值，于是 COUNT(Grade) 不计缺考、AVG(Grade) 的分母也不含缺考。

分组用 GROUP BY，值相等为一组，聚集函数分别作用于每组；HAVING 对组再筛。【例 3.46】SELECT Cno, COUNT(Sno) FROM SC GROUP BY Cno; 求各课选课人数。【例 3.47】SELECT Sno FROM SC GROUP BY Sno HAVING COUNT(*) > 3; 选课 3 门以上。【例 3.48】平均分 ≥ 90：条件里含聚集函数，必须写 HAVING，不能写 WHERE。

考点 · 必背

WHERE 与 HAVING 的分工，以及分组查询的合法目标列：

  • WHERE 作用于元组（分组前），只能用列名、常量，不能用聚集函数；HAVING 作用于组（分组后），只能引用 GROUP BY 中出现过的列或聚集函数。
  • 分组查询的 SELECT 目标列只允许出现聚集函数和 GROUP BY 中出现过的列，否则结果无意义。
  • 执行顺序（补充）：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY。这解释了"SELECT 里的别名不能在 WHERE 中用，但 ORDER BY 可以用"。
  • COUNT(*) 统计行数（含全空行），COUNT(列) 只统计该列非空值，COUNT(DISTINCT 列) 再对非空值去重。

易错

课件第 116 页"查询每门课程的及格人数"给出的 SELECT Cno, COUNT(Sno) FROM SC GROUP BY Cno HAVING Grade>=60 是错句：Grade 既不在 GROUP BY 中，也不是聚集函数，且 HAVING 里不能引用未分组的单行属性。正确写法是把条件下推到 WHERE：SELECT Cno, COUNT(Sno) FROM SC WHERE Grade>=60 GROUP BY Cno;。这条错误几乎年年出现在选择题里，务必记成"行条件进 WHERE，组条件进 HAVING"。

例题

【例 3.48】查询平均成绩大于等于 90 分的学生学号和平均成绩，并说明为什么不能把条件写在 WHERE 中。

SELECT Sno, AVG(Grade) FROM SC GROUP BY Sno HAVING AVG(Grade) >= 90;。原因：WHERE 在分组前逐元组过滤，此时 AVG(Grade) 尚未计算，SQL 规定聚集函数不能出现在 WHERE 中；HAVING 在分组后对每组求值，才能用 AVG。若题目改成"查询有课程成绩 ≥ 90 的学生"，条件针对单行，则应写 WHERE Grade >= 90。

口诀：行筛选 WHERE，组筛选 HAVING；聚集不进 WHERE，分组列才进 SELECT——前三句定位置，最后一句定合法性。

本节小结

  • SELECT 管"列"（表达式、别名、DISTINCT），WHERE 管"行"（六类条件），ORDER BY 管"序"，聚集函数 + GROUP BY/HAVING 管"组"。
  • LIKE 的两个通配符与 ESCAPE 转义是必考细节，'_' 的个数要与"第几个字"对上。
  • 聚集函数跳过 NULL（COUNT(*) 除外），HAVING 才能用聚集函数，分组后 SELECT 只能出现分组列与聚集函数。

3.4.2连接查询：等值、自身、外连接与多表

连接条件的一般形式是 [表1.]列1 θ [表2.]列2，也可用 BETWEEN … AND …。连接字段的类型必须可比，但名字不必相同——这句是判断题常考点。若在 SELECT 中直接写 *，等值连接结果会保留两个重复的连接列，自然连接则要去掉重复列。

-- 【例 3.49】等值连接：每个学生及其选课情况
SELECT Student.*, SC.*
FROM   Student, SC
WHERE  Student.Sno = SC.Sno;

-- 【例 3.50】自然连接：去掉重复的 Sno 列
SELECT Student.Sno, Sname, Ssex, Sage, Sdept, Cno, Grade
FROM   Student, SC
WHERE  Student.Sno = SC.Sno;

-- 【例 3.51】选择与连接复合：选 2 号课且 90 分以上
SELECT Student.Sno, Sname
FROM   Student, SC
WHERE  Student.Sno = SC.Sno AND SC.Cno = '2' AND SC.Grade > 90;

连接操作的执行有三种算法（第 10 章详讲）：嵌套循环法（外表每个元组扫一遍内表）、排序合并法（先按连接属性排序，再双向顺序扫描，常用于 = 连接）、索引连接（对内表连接字段建索引，外表全扫描、内表查索引）。考"哪种方法适合等值连接"答排序合并与索引连接。

自身连接是"一张表与自己连接"，必须起两个别名，且所有同名列前必须加别名前缀。【例 3.52】查每门课的间接先修课：

SELECT FIRST.Cno, SECOND.Cpno
FROM   Course FIRST, Course SECOND
WHERE  FIRST.Cpno = SECOND.Cno;      -- 结果：(1,7)、(3,5)、(5,6)

为什么只有 3 行？因为 2 号、6 号课 Cpno 为空，4 号课的先修课 6 号其 Cpno 也为空，7 号课的先修课 6 号同样为空，这些行在等值条件下自然被淘汰。自身连接的另一种典型用法是"既选修 1 号又选修 2 号"：FROM SC X, SC Y WHERE X.Sno=Y.Sno AND X.Cno='1' AND Y.Cno='2'。

外连接以指定表为"主体"，把主体表中不满足连接条件的元组也输出，缺失列补 NULL：LEFT OUTER JOIN 保留左表全部元组，RIGHT 保留右表，FULL 两边都保留。【例 3.53】

SELECT Student.Sno, Sname, Ssex, Sage, Sdept, Cno, Grade
FROM   Student LEFT OUTER JOIN SC ON (Student.Sno = SC.Sno);

结果比【例 3.49】多出两行：王敏（MA）与张立（IS）没有选课，Cno、Grade 补 NULL。多表连接则是把多个连接条件用 AND 串起来，【例 3.54】查每个学生的学号、姓名、课程名、成绩需要 Student、SC、Course 三表：

SELECT Student.Sno, Sname, Cname, Grade
FROM   Student, SC, Course
WHERE  Student.Sno = SC.Sno AND SC.Cno = Course.Cno;

易错

外连接的条件位置决定语义：LEFT JOIN … ON (A=B AND 其他条件) 与 LEFT JOIN … ON (A=B) WHERE 其他条件 不等价——后者会把补 NULL 的行过滤掉，退化成内连接。课件第 100 页"查找不为 BOC 工作的员工"给出的 LEFT JOIN … WHERE w.ID IS NULL 正是利用这一性质做反连接，属于正确用法；若把 w.company_name='BOC' 写进 WHERE，结果就错了。另一个错点：写 SELECT Sname, Sno 这类多表查询时，若列名只出现在一张表中可不加前缀，但凡出现同名列必须加表名前缀，否则报"列名歧义"。

例题

用 JOIN 改写【例 3.51】，并指出课件第 14 页写法的错误。

正确写法：SELECT Student.Sno, Sname FROM SC INNER JOIN Student ON Student.Sno = SC.Sno WHERE SC.Cno='2' AND SC.Grade>90;。课件写作 ON Student.Sno = SC.Cno，把学号与课程号相连，属于连接字段错配，结果必错。JOIN 写法与逗号写法语义相同，但 ON 只写连接条件、WHERE 只写选择条件，结构更清晰。

3.4.3嵌套查询：IN、ANY/ALL 与 EXISTS 的双重否定

一个 SELECT-FROM-WHERE 叫一个查询块，把一个查询块嵌进另一个查询块的 WHERE 或 HAVING 条件中就是嵌套查询。上层叫外层查询（父查询），下层叫内层查询（子查询）。子查询不能使用 ORDER BY，ORDER BY 只能对最终结果排序；子查询的 SELECT 列数必须与父查询的比较对象匹配。

按求解方式分两类，这是理解所有嵌套题的关键：不相关子查询由里向外逐层求解，子查询先算出一个集合，再交给父查询；相关子查询的子查询条件依赖父查询的当前元组，父查询每取一行就要把该行的值传给子查询重算一遍，因此必须用别名区分内外层。

-- 【例 3.55】与"刘晨"在同一个系学习的学生（不相关子查询）
SELECT Sno, Sname, Sdept
FROM   Student
WHERE  Sdept IN (SELECT Sdept FROM Student WHERE Sname = '刘晨');

-- 【例 3.56】选修了"信息系统"的学生（两层 IN 嵌套）
SELECT Sno, Sname
FROM   Student
WHERE  Sno IN (SELECT Sno FROM SC
               WHERE Cno IN (SELECT Cno FROM Course
                             WHERE Cname = '信息系统'));

-- 【例 3.57】找出每个学生超过他自己选修课程平均成绩的课程号（相关子查询）
SELECT Sno, Cno
FROM   SC x
WHERE  Grade >= (SELECT AVG(Grade) FROM SC y WHERE y.Sno = x.Sno);

【例 3.56】用连接查询也能做，且通常效率更高：FROM Student, SC, Course WHERE Student.Sno=SC.Sno AND SC.Cno=Course.Cno AND Course.Cname='信息系统'。当能确定内层返回单值时，可用比较运算符（=、>、< 等）代替 IN——【例 3.55】一个学生只在一个系，故 Sdept = (SELECT …) 合法；若子查询可能返回多行，用 = 会运行时报错。

ANY/SOME/ALL 必须与比较运算符连用：>ANY 表示大于子查询结果中的某个值（即大于最小值），>ALL 表示大于所有值（即大于最大值）。【例 3.58】非 CS 系中比 CS 系任意一个学生年龄小：WHERE Sage < ANY (SELECT Sage FROM Student WHERE Sdept='CS') AND Sdept <> 'CS'; 结果王敏 18、张立 19。【例 3.59】比 CS 系所有学生都小，用 < ALL，等价于 < (SELECT MIN(Sage) …)。用聚集函数的写法效率高于 ANY/ALL，这是课件明确给出的结论。

EXISTS 代表存在量词 ∃，带 EXISTS 的子查询不返回任何数据，只产生真值 TRUE/FALSE：内层结果非空为真，为空为假；NOT EXISTS 相反。因此 EXISTS 子查询的目标列通常写 *，写什么列都不影响语义。【例 3.60】选修了 1 号课程的学生姓名：WHERE EXISTS (SELECT * FROM SC WHERE Sno=Student.Sno AND Cno='1')；【例 3.61】没选修 1 号课：把 EXISTS 换成 NOT EXISTS。所有带 IN、比较运算符、ANY/ALL 的子查询都能等价改写成 EXISTS 形式，反之不成立——EXISTS 表达能力更强。

考点 · 必背

用 EXISTS 表达全称量词，是全章最难也最爱考的一题，背模板 + 记语义：

  • SQL 没有全称量词 ∀，转换公式：(∀x)P ≡ ¬(∃x(¬P))。"选修了全部课程"＝"不存在一门课程他没选"。
  • 【例 3.62】模板（两层 NOT EXISTS，外层遍历 Student，中层遍历 Course，内层查 SC）：
    SELECT Sname FROM Student WHERE NOT EXISTS (SELECT * FROM Course WHERE NOT EXISTS (SELECT * FROM SC WHERE Sno=Student.Sno AND Cno=Course.Cno));
  • 逻辑蕴涵 p→q ≡ ¬p∨q ≡ ¬(p∧¬q)。"至少选修了 202215122 所选的全部课程"＝"不存在一门 202215122 选了而 x 没选的课"，用 NOT EXISTS 套 NOT EXISTS，内层条件是 SCY.Sno='202215122' AND NOT EXISTS(该生选了同一 Cno)。
  • 写完后自检：最内层子查询的 WHERE 必须把外层学号、中层课程号同时绑上，缺一个就退化成"存在任意选课记录"。

易错

三个真实会扣分的坑：① NOT IN 遇 NULL 全盘失效（补充）：若子查询结果含 NULL，x NOT IN (…NULL…) 对任何 x 都返回 UNKNOWN，查询结果为空；此时应改用 NOT EXISTS。② EXISTS 与 IN 的去重效果不同：EXISTS 只判存在性，不产生重复；IN 可能因外层重复行而重复，需要 DISTINCT。③ 把"选修了全部课程"写成 COUNT(*)=(SELECT COUNT(*) FROM Course) 的 GROUP BY 形式虽可得分，但若课程有重复选课记录会算错，标准答案仍是双重 NOT EXISTS。

例题

【例 3.62】查询选修了全部课程的学生姓名，并说明每一层 NOT EXISTS 的含义。

语句见上方 kp 模板。语义逐层拆：最内层"该学生选了这门课"，中层"存在一门该学生没选的课"，最外层 NOT EXISTS 把它否定，即"不存在他没选的课"，也就是全部课程都选了。评分点：两层 NOT EXISTS 各 2 分，内层 WHERE 同时绑定 Sno 与 Cno 得 3 分，外层 SELECT Sname 得 1 分。若学生一门课都没选，内层 NOT EXISTS 恒真、中层 EXISTS 为真、外层为假，不会误选，逻辑自洽。

口诀：全部＝没有一门没有；至少（蕴涵）＝没有一门他有我没有——前者两层 NOT EXISTS 夹 Course，后者两层 NOT EXISTS 夹"202215122 选过的课"。

本节小结

  • 不相关子查询由里向外一次算完；相关子查询逐行代入，必须用别名区分内外层。
  • IN/比较/ANY/ALL 都能改写成 EXISTS；ANY 配聚集函数可读性更好、效率更高，考试两种写法都算对。
  • "全部""至少全部"两类题一律双重 NOT EXISTS，先写语义再套模板，最后检查内层是否同时绑定两个外层列。

3.4.4集合查询、派生表与 SELECT 一般格式

集合查询把两个查询结果做并、交、差：UNION、INTERSECT、EXCEPT。参加运算的各结果列数必须相同，对应列的数据类型也必须相同；ORDER BY 只能写在最后。UNION 自动去重，UNION ALL 保留重复元组。

-- 【例 3.64】CS 系学生 并 年龄不大于 19 岁的学生
SELECT * FROM Student WHERE Sdept = 'CS'
UNION
SELECT * FROM Student WHERE Sage <= 19;

-- 【例 3.66】交集；【例 3.68】差集
SELECT * FROM Student WHERE Sdept = 'CS'
INTERSECT
SELECT * FROM Student WHERE Sage <= 19;

SELECT * FROM Student WHERE Sdept = 'CS'
EXCEPT
SELECT * FROM Student WHERE Sage <= 19;

注意【例 3.64】到【例 3.68】都在提示同一件事：能用 AND/OR 或 IN 写清的，就别硬套集合运算。交集等价于 Sdept='CS' AND Sage<=19，差集等价于 Sdept='CS' AND Sage>19，并集在单表上也可用 OR。集合运算真正的用武之地是"跨表结构相同"或"用 EXCEPT 表达包含"：【例 3.63】"至少选修了 202215122 全部课程"＝"202215122 的选课集合 减去 该生的选课集合 为空"，即"A 包含 B ≡ 不存在 (B 减 A)"，可先用两个 SELECT 做 EXCEPT 再套 NOT EXISTS。

派生表是放在 FROM 子句里的子查询，相当于一张临时表，必须给别名；若子查询含聚集函数或表达式列，还要用 别名(列名,…) 指定列名。【例 3.57】的派生表写法：

SELECT Sno, Cno
FROM   SC, (SELECT Sno, AVG(Grade) FROM SC GROUP BY Sno)
           AS Avg_sc(avg_sno, avg_grade)
WHERE  SC.Sno = Avg_sc.avg_sno AND SC.Grade >= Avg_sc.avg_grade;

若子查询中没有聚集函数，列名可省略，直接用子查询 SELECT 出的列名（【例 3.60】的 (SELECT Sno FROM SC WHERE Cno='1') AS SC1）。

SELECT 的一般格式（3.4.6）是答卷前的"检查清单"：

SELECT [ALL|DISTINCT] <目标列表达式> [别名] [, …]
FROM   <表名或视图名> [别名] [, …] | (<SELECT 语句>) [AS] <别名>
[WHERE <条件表达式>]
[GROUP BY <列名> [HAVING <条件表达式>]]
[ORDER BY <列名> [ASC|DESC]];

目标列表达式有四种合法形态：*、表名.*、聚集函数、由列/聚集函数/常量经 + − × ÷ 组成的表达式。WHERE 条件有七种形态：比较、BETWEEN、IN、LIKE、IS NULL、EXISTS、由 AND/OR/NOT 连接的复合条件。

易错

INTERSECT 与 EXCEPT 不是所有系统都支持（补充：MySQL 8.0 之前没有，需用 JOIN 或 EXISTS 改写），答题时若题目限定"标准 SQL"才可放心用。另一个高频错点是把 ORDER BY 写进子查询或派生表——标准不允许（除非同时用 LIMIT），排序只能作用于最终结果。

口诀：选列 FROM 表，WHERE 挑行，GROUP 分组，HAVING 筛组，ORDER 排序——写 SQL 时按这五步填，就不会把条件放错子句。

3.5数据更新：INSERT、UPDATE、DELETE

插入有两种：插入元组与插入子查询结果。列名可省略，省略时表示要插入完整元组且属性顺序与表定义一致；只给部分列时，其余列取空值。VALUES 的个数、类型必须与 INTO 子句匹配。

-- 【例 3.69】插入一个学生元组
INSERT INTO Student (Sno, Sname, Ssex, Sdept, Sage)
VALUES ('202215128', '陈冬', '男', 'IS', 18);

-- 【例 3.71】只给学号、课程号，Grade 自动为空
INSERT INTO SC (Sno, Cno) VALUES ('202215128', '1');

-- 【例 3.72】按系求平均年龄并存入新表
CREATE TABLE Dept_age (Sdept CHAR(15), Avg_age SMALLINT);
INSERT INTO Dept_age (Sdept, Avg_age)
SELECT Sdept, AVG(Sage) FROM Student GROUP BY Sdept;

插入子查询结果时，SELECT 的目标列必须与 INTO 子句的列在个数和类型上一一对应，且子查询中不能引用正在被插入的表（补充：否则可能自我引用导致不确定结果，一般先查完再插入）。执行插入时系统会检查实体完整性、参照完整性和用户定义完整性（NOT NULL、UNIQUE、值域）。

-- 【例 3.73】改一个元组；【例 3.74】全表加 1 岁
UPDATE Student SET Sage = 22 WHERE Sno = '202215121';
UPDATE Student SET Sage = Sage + 1;

-- 【例 3.75】带子查询：CS 系全体学生成绩置零
UPDATE SC SET Grade = 0
WHERE Sno IN (SELECT Sno FROM Student WHERE Sdept = 'CS');

UPDATE 的 SET 子句可用表达式，也可用子查询（如"把 D01 系主任工资改为该系平均工资"）。省略 WHERE 表示修改表中所有元组；修改时主码不允许改，其他列要满足实体完整性、用户定义完整性。

-- 【例 3.76】删一个元组；【例 3.77】删全部选课记录
DELETE FROM Student WHERE Sno = '202215128';
DELETE FROM SC;

-- 【例 3.78】带子查询：删 CS 系学生的选课记录
DELETE FROM SC
WHERE Sno IN (SELECT Sno FROM Student WHERE Sdept = 'CS');

易错

三个"删不干净"的混淆：DELETE 只删元组，表的定义仍在数据字典中；DROP TABLE 才删定义、数据和索引；TRUNCATE（补充，SQL2008 引入）删全部行但不写日志、不可回滚，与 DELETE FROM 表 不同。另外，省略 WHERE 的 UPDATE/DELETE 会作用于全表，是上机题最常见的误操作；带子查询修改时若子查询又引用被修改的表，各系统限制不同，标准答案一般先建临时表或分两步执行。

例题

【例 3.72】对每一个系求学生平均年龄并存入数据库，写出完整两步语句，并说明字段类型为什么这样选。

第一步建表：CREATE TABLE Dept_age (Sdept CHAR(15), Avg_age SMALLINT);；第二步插入：INSERT INTO Dept_age (Sdept, Avg_age) SELECT Sdept, AVG(Sage) FROM Student GROUP BY Sdept;。要点：① 先建表后插入，不能直接 INSERT 到不存在的表；② 目标列个数、类型与 SELECT 一致（CHAR(15) 容纳系名，SMALLINT 容纳平均年龄）；③ AVG 结果是数值，赋给 SMALLINT 会按系统规则取整，若要求精确应改 DECIMAL(4,1)。

3.6空值的处理：三值逻辑与它挖的坑

空值 NULL 表示"不知道""不存在"或"无意义"，三种来源：该属性应有值但暂时不知道；该属性本不该有值；因某种原因不便填写。它带来不确定性，必须特殊处理。产生空值的途径有：插入时未赋值或显式写 NULL（【例 3.79】INSERT INTO SC(Sno,Cno) VALUES('202215126','1'); Grade 自动为空）、UPDATE 把某列置 NULL（【例 3.80】）、外连接给缺失列补 NULL、以及空值参与运算产生新的空值（补充：NULL+1 仍为 NULL）。

判断空值只能用 IS NULL / IS NOT NULL，绝不能用 = NULL（【例 3.36】）。约束方面有三条硬规则：有 NOT NULL 约束的列不能取空值；码属性不能取空值；加了 UNIQUE 约束的列可以取空值（且多行可同时为空）。

运算规则是全章最容易被判断题坑的地方：空值与另一个值（包括另一个空值）的算术运算结果为空值；比较运算结果为 UNKNOWN。有了 UNKNOWN，二值逻辑扩展为三值逻辑：NOT UNKNOWN = UNKNOWN；TRUE AND UNKNOWN = UNKNOWN，FALSE AND UNKNOWN = FALSE；TRUE OR UNKNOWN = TRUE，FALSE OR UNKNOWN = UNKNOWN，UNKNOWN OR UNKNOWN = UNKNOWN。WHERE 子句只保留条件为 TRUE 的元组，UNKNOWN 与 FALSE 一样被丢弃。

-- 【例 3.82】选 1 号课不及格的学生：缺考的不会出现
SELECT Sno FROM SC WHERE Grade < 60 AND Cno = '1';

-- 【例 3.83】不及格 或 缺考：必须显式判空
SELECT Sno FROM SC
WHERE Cno = '1' AND (Grade < 60 OR Grade IS NULL);

考点 · 必背

空值四问，简答与判断都从这里出：

  • 怎么产生：插入未赋值、显式 NULL、UPDATE 置空、外连接补空、空值参与运算。
  • 怎么判断：IS [NOT] NULL；= NULL 恒为 UNKNOWN，永远查不到行。
  • 受什么约束：NOT NULL 列与码属性不可空；UNIQUE 列可空。
  • 怎么运算：算术得 NULL，比较得 UNKNOWN，逻辑按三值真值表；聚集函数除 COUNT(*) 外一律跳过 NULL。

易错

四个连环坑：① AVG 的分母：AVG(Grade) 只除以有成绩的人数，缺考不计入，与"按人选课人数求平均"含义不同。② COUNT(*) 与 COUNT(Grade) 结果可能差很多，前者含缺考行。③ NOT IN 遇 NULL：Sno NOT IN (SELECT Sno FROM SC WHERE Cno='1') 若子查询结果含 NULL，整个条件恒为 UNKNOWN。④ CHECK 约束遇 NULL（补充）：SQL 规定 CHECK 条件求值为 UNKNOWN 时不拒绝，只有明确为 FALSE 才拒绝——这正是 SC 的 Grade 约束要写 Grade IS NULL OR … 的原因。

3.7视图：虚表、消解法与可更新性判定

视图是从一个或几个基本表（或视图）导出的表，数据库中只存放视图的定义，不存放对应的数据，是虚表；基表数据一变，查视图的结果随之改变。

CREATE VIEW <视图名> [(<列名> [, <列名>]…)]
AS <子查询>
[WITH CHECK OPTION];

DROP VIEW <视图名> [CASCADE];

组成视图的属性列名要么全省略、要么全指定，不能只指定一部分。三种情况必须显式指定列名：某个目标列是聚集函数或表达式；多表连接时选出了同名列；需要给列换更合适的名字。【例 3.84】建信息系学生视图 IS_Student；【例 3.85】加 WITH CHECK OPTION，此后对该视图做 INSERT/UPDATE/DELETE 时，RDBMS 自动加上 Sdept='IS' 的条件，保证更新后的行仍满足视图定义。若视图由单个基本表导出、只去掉了某些行和列但保留了主码，称为行列子集视图，IS_Student 即是。

其余几类视图要能对号入座：【例 3.86】基于多个基表的视图 IS_S1（必须指定列名，因为 Sno 同名列出现）；【例 3.87】基于视图的视图 IS_S2；【例 3.88】带表达式的视图 BT_S（2014-Sage 必须起别名 Sbirth）；【例 3.89】分组视图 S_G（含聚集函数，必须指定列名）；【例 3.90】用 SELECT * 定义的 F_Student，缺点是一旦基表增加列，视图与基表的映像被破坏，这是"不要用 SELECT * 建视图"的标准理由。

删除视图用 DROP VIEW，若该视图还导出了其他视图，需 CASCADE 级联删除（【例 3.91】删 IS_S1 会连带 IS_S2）。查询视图与查基本表写法相同，系统用视图消解法处理：有效性检查 → 把视图定义中的子查询与用户查询合并成等价的基本表查询 → 执行。

-- 【例 3.92】查信息系年龄小于 20 的学生，消解后为：
SELECT Sno, Sage FROM Student WHERE Sdept = 'IS' AND Sage < 20;

-- 【例 3.94】S_G 视图上查平均分≥90：直接写 WHERE Gavg>=90 会失败
SELECT Sno, AVG(Grade) FROM SC GROUP BY Sno HAVING AVG(Grade) >= 90;

视图消解法的局限：当视图定义含聚集函数和 GROUP BY 时，把 WHERE Gavg>=90 机械下推会得到 WHERE AVG(Grade)>=90 这种非法语句，正确做法是把条件改写成 HAVING，或用派生表 FROM (SELECT Sno, AVG(Grade) …) AS S_G(Sno,Gavg) WHERE Gavg>=90。

更新视图最终都转换成对基本表的更新：【例 3.95】改 IS_Student 中某学生姓名 → UPDATE Student … WHERE Sno=… AND Sdept='IS'；【例 3.96】向 IS_Student 插记录 → 向 Student 插入且 Sdept 补 'IS'；【例 3.97】删记录同样补上系条件。但 S_G 这类含聚集函数的视图不可更新：UPDATE S_G SET Gavg=90 无法唯一地转换成对 SC 的更新。

考点 · 必背

视图可更新性判定，考场上按"逐条排除"做，只要命中一条即不可更新（DB2 规定，课件原文）：

  • 行列子集视图一定可更新；由两个以上基本表导出的视图不可更新。
  • 字段来自表达式或常量：不允许 INSERT、UPDATE，但允许 DELETE。
  • 字段来自聚集函数、定义含 GROUP BY、定义含 DISTINCT：一律不可更新。
  • 定义中有嵌套查询，且内层 FROM 涉及导出该视图的基本表：不可更新；在不允许更新的视图上再定义的视图，也不可更新。
  • 加了 WITH CHECK OPTION 的视图仍可更新，只是更新必须满足视图定义的谓词。

视图的作用五条，简答题按点给分：简化用户操作（多表连接、复杂嵌套、导出属性都可封装）；使用户能以多种角度看待同一数据；对重构数据库提供一定程度的逻辑独立性——Student 垂直分成 SX(Sno,Sname,Sage) 与 SY(Sno,Ssex,Sdept) 后，重建同名视图 Student 即可让应用程序不改；对机密数据提供安全保护（不同用户看不同视图）；适当使用可更清晰地表达查询（如先建 VMGRADE 求每人最高分，再连接 SC 取课程号）。

易错

视图的"逻辑独立性"只是一定程度的：由于更新视图有条件，应用程序中修改数据的语句仍可能因基表结构改变而失效，这句限定词经常是简答题的扣分点。另外，"视图不存储数据"不等于"视图不占空间"——数据字典里要存视图定义；CREATE VIEW 时系统只把定义存入数据字典，并不执行其中的 SELECT，这也是判断题高频句。

例题

【例 3.94】在 S_G 视图（Sno, Gavg）中查询平均成绩在 90 分以上的学生，为什么不能直接写 WHERE Gavg>=90？给出两种正确写法。

因为 S_G 由 SELECT Sno, AVG(Grade) FROM SC GROUP BY Sno 定义，视图消解会把 Gavg 替换成 AVG(Grade)，得到 WHERE AVG(Grade)>=90，而聚集函数不能出现在 WHERE 中，语句非法。正确写法一（改 HAVING）：SELECT Sno, AVG(Grade) FROM SC GROUP BY Sno HAVING AVG(Grade)>=90;；写法二（派生表）：SELECT * FROM (SELECT Sno, AVG(Grade) FROM SC GROUP BY Sno) AS S_G(Sno,Gavg) WHERE Gavg>=90;。评分点：指出消解后 WHERE 中出现聚集函数（3 分），两种改法各 2 分。

本节小结

  • 视图 = 存储起来的查询定义，虚表；查询靠消解，更新靠转换。
  • 可更新性：行列子集视图可更新；聚集、GROUP BY、DISTINCT、多表、表达式列、自引用嵌套一律不可更新（表达式列仅允许 DELETE）。
  • WITH CHECK OPTION 管的是"通过视图更新后仍满足视图条件"，不是禁止更新。

3.8本章小结与答题模板

SQL 分数据定义、数据查询、数据更新、数据控制四大部分，本章覆盖前三部分，数据控制留到第 4 章。它是关系数据库语言的工业标准：多数产品支持 SQL92，对 SQL99 之后的标准只支持部分特征，至今没有一个系统完全支持 SQL99 以上的标准。

本章在期末卷中的题面几乎固定为三类：① 给要求写 SQL（4～6 小题，每小题 3～5 分）；② 给语句问结果或改错；③ 视图/索引/空值/嵌套的概念简答。写 SQL 的通用流程是：

  1. 定表：看输出列和条件涉及哪些表，列全需要的表一个不能少；同表用两次就起两个别名。
  2. 定行：单行条件进 WHERE，组条件进 HAVING，别把聚集函数塞进 WHERE。
  3. 定形：需要"全部/至少全部"用双重 NOT EXISTS；需要"存在"用 EXISTS 或 IN；需要"不存在"优先 NOT EXISTS 而非 NOT IN。
  4. 定序与去重：最终结果才 ORDER BY；只输出 Sno 时判断要不要 DISTINCT。
  5. 查漏：核对字符串常量加引号、日期格式、NULL 用 IS、多表连接条件是否写全（漏一个就是笛卡尔积）。

全章小结

  • 一条主线：建（模式/表/索引）→ 查（单表→连接→嵌套→集合→派生表）→ 改（增删改）→ 用（视图封装）。
  • 两个"必须默写"：Student/Course/SC 建表语句；双重 NOT EXISTS 表达"全部"的模板。
  • 三个"必考判断"：WHERE 与 HAVING 的分工、视图可更新性、空值比较得 UNKNOWN。
  • 四个高频失分点：LIKE 中下划线个数、连接条件漏写、NOT IN 遇 NULL、聚集函数写进 WHERE。
