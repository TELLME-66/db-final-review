1三级模式与数据独立性 ★

表 1　三级模式的分工与数量
层次名称对应对象数量谁使用
外模式子模式 / 用户模式视图（局部数据的逻辑结构）多个应用程序、最终用户
模式逻辑模式全体基本表（全局逻辑结构）唯一DBA、设计人员
内模式存储模式存储文件、索引、存储结构唯一DBMS 内部
  • 外模式/模式映像：模式改变时只要改映像、应用程序不变 → 逻辑独立性。例：基本表增加一列、拆分表，视图定义不变。
  • 模式/内模式映像：存储结构改变（换索引、换文件组织）时只要改映像、模式不变 → 物理独立性。
  • 一句话：映像保独立，外模式保安全，模式保全局。三级模式是「结构的三个层次」，两级映像是「两种独立性的实现机制」。

易错

「一个数据库只有一个模式和一个内模式，但可以有多个外模式」——数量关系必考；「视图对应外模式，基本表对应模式，存储文件对应内模式」也要能对上。

2SQL 建表与三类完整性 ★

-- 学生-课程库：所有 SQL 题的公共模式
CREATE TABLE Student (
  Sno    CHAR(9)  PRIMARY KEY,          -- 实体完整性
  Sname  CHAR(20) UNIQUE NOT NULL,
  Ssex   CHAR(2)  CHECK (Ssex IN ('男','女')),
  Sage   SMALLINT CHECK (Sage BETWEEN 15 AND 45),
  Sdept  CHAR(20)
);
CREATE TABLE Course (
  Cno     CHAR(4) PRIMARY KEY,
  Cname   CHAR(40) NOT NULL,
  Cpno    CHAR(4),                       -- 先修课，自反参照
  Ccredit SMALLINT,
  FOREIGN KEY (Cpno) REFERENCES Course(Cno)
);
CREATE TABLE SC (
  Sno   CHAR(9),
  Cno   CHAR(4),
  Grade SMALLINT,
  PRIMARY KEY (Sno, Cno),                -- 实体完整性（组合码）
  FOREIGN KEY (Sno) REFERENCES Student(Sno) ON DELETE CASCADE,
  FOREIGN KEY (Cno) REFERENCES Course(Cno)
);
表 2　三类完整性：定义、检查时机、违约处理
完整性定义子句检查时机违约处理
实体完整性PRIMARY KEY插入、更新主码拒绝（No Action）
参照完整性FOREIGN KEY … REFERENCES …插入/更新外码；删除/更新被参照的主码NO ACTION / RESTRICT（默认拒绝）、CASCADE、SET NULL
用户定义完整性NOT NULL、UNIQUE、CHECK、DEFAULT插入、更新拒绝

易错

① 外码可以取空值（除非列上加了 NOT NULL），但主码不能为空；② 参照完整性违约处理要写清「删除被参照元组」和「更新被参照主码」两种情形；③ CHECK 是属性/元组级，跨表的复杂约束要用断言或触发器。

3SQL 查询模板 ★

SELECT [ALL|DISTINCT] 目标列 [,…]
FROM 表/视图 [,…]
[WHERE 条件]
[GROUP BY 列 [,…] [HAVING 组条件]]
[ORDER BY 列 [ASC|DESC]];

-- 单表：范围、集合、空值、模糊
SELECT Sname FROM Student WHERE Sage BETWEEN 20 AND 23;
SELECT Sno FROM SC WHERE Grade IS NULL;          -- 空值只能用 IS (NOT) NULL
SELECT Sname FROM Student WHERE Sname LIKE '刘%' ESCAPE '\';

-- 聚集 + 分组 + 组条件
SELECT Cno, COUNT(*) AS 人数, AVG(Grade) AS 平均分
FROM SC GROUP BY Cno HAVING COUNT(*) >= 10;

-- 连接：等值、自身、外连接
SELECT Student.Sno, Sname, Cname, Grade
FROM Student, SC, Course
WHERE Student.Sno = SC.Sno AND SC.Cno = Course.Cno;
SELECT S1.Sno, S1.Sname FROM Student S1, Student S2
WHERE S1.Sdept = S2.Sdept AND S2.Sname = '刘晨' AND S1.Sname <> '刘晨';
SELECT Student.Sno, Sname, Cno, Grade FROM Student
LEFT OUTER JOIN SC ON Student.Sno = SC.Sno;       -- 没选课的学生也列出

-- 嵌套：IN / 比较 / ANY / ALL
SELECT Sname FROM Student
WHERE Sno IN (SELECT Sno FROM SC WHERE Cno = '1');
SELECT Sname FROM Student
WHERE Sage > ALL (SELECT Sage FROM Student WHERE Sdept = 'CS');

-- EXISTS：相关子查询；双重 NOT EXISTS 表达“全部”
SELECT Sname FROM Student S
WHERE NOT EXISTS (
  SELECT * FROM Course C
  WHERE NOT EXISTS (
    SELECT * FROM SC WHERE SC.Sno = S.Sno AND SC.Cno = C.Cno));

-- 集合查询
SELECT Sno FROM SC WHERE Cno = '1'
UNION SELECT Sno FROM SC WHERE Cno = '2';

考点 · 必背的三种固定写法

  • 「全部」＝没有一门课是他没选的：NOT EXISTS (… WHERE NOT EXISTS (…))，外层遍历学生、中层遍历课程、内层查选课。
  • 「至少选了 x 所选全部课程」＝不存在「x 选了而他没选」的课：把上一式中层改成 SELECT * FROM SC X WHERE X.Sno = '202215122'。
  • 「没有选课的学生」：LEFT JOIN … WHERE SC.Sno IS NULL 或 NOT IN (SELECT Sno FROM SC)。

易错

① WHERE 中不能用聚集函数，聚集条件只能进 HAVING；② 分组后 SELECT 只能出现分组列和聚集函数；③ COUNT(*) 统计行数、COUNT(列) 跳过 NULL；④ 字符串比较、日期格式与 NOT IN 遇 NULL 返回 UNKNOWN（查不出任何行）。

表 3　五种基本运算 + 四个组合运算
运算符号含义SQL 对应
并R ∪ S属于 R 或属于 S 的元组（同元）UNION
差R − S属于 R 而不属于 SEXCEPT / NOT IN
交R ∩ S同时属于两者INTERSECT
笛卡尔积R × S任意组合FROM R, S

投影π列(R)选列（自动去重）SELECT DISTINCT

考点 · 除运算三行公式

设 R(X,Y)、S(Y)，则 R ÷ S = πX(R) − πX( (πX(R) × S) − R )。
含义：先造出「所有 x 与所有 y 的组合」，减去 R 中已有的，剩下的就是「缺了某些 y 的 x」，再从全部 x 中减掉它们。

易错

关系代数没有「计数」，遇到「选修了 3 门以上」要么用 SQL，要么写成「存在 3 个不同课程」的复杂表达式；投影默认去重，SQL 要写 DISTINCT；自然连接按同名属性连接，不写连接条件。

5授权、角色、视图、触发器 ★

-- 授权与回收
GRANT SELECT, UPDATE(Sage) ON TABLE Student TO U1 WITH GRANT OPTION;
GRANT ALL PRIVILEGES ON TABLE SC TO U2, U3;
REVOKE SELECT ON TABLE Student FROM U1 CASCADE;   -- 级联回收它转授的权限

-- 角色
CREATE ROLE R1;
GRANT SELECT, INSERT ON TABLE Student TO R1;
GRANT R1 TO U1;          -- 把角色授予用户
REVOKE R1 FROM U1;

-- 视图充当安全机制
CREATE VIEW CS_Student AS
  SELECT Sno, Sname, Sage FROM Student WHERE Sdept = 'CS'
  WITH CHECK OPTION;     -- 更新不得破坏视图定义
GRANT SELECT ON CS_Student TO U4;

-- 触发器：行级 + WHEN
CREATE TRIGGER SC_T AFTER UPDATE OF Grade ON SC
REFERENCING OLD AS OldTuple NEW AS NewTuple
FOR EACH ROW
WHEN (NewTuple.Grade >= 1.1 * OldTuple.Grade)
INSERT INTO SC_U(Sno, Cno, OldGrade, NewGrade)
VALUES (OldTuple.Sno, OldTuple.Cno, OldTuple.Grade, NewTuple.Grade);
表 4　四种安全/完整性机制的定位
机制解决的问题粒度典型语句
视图隐藏行列、简化查询表 / 列 / 行CREATE VIEW … WITH CHECK OPTION
授权谁能对什么做什么表 / 列GRANT / REVOKE
角色权限批量管理权限集合CREATE ROLE / GRANT 角色
审计事后追查用户级 / 系统级AUDIT / 审计日志
触发器复杂业务规则、跨表约束行级 / 语句级CREATE TRIGGER
断言跨表、聚合类约束数据库级CREATE ASSERTION

易错

视图可更新的条件：由单个基本表导出、保留主码、只做选择与投影（不含聚集、分组、DISTINCT、表达式列）；含这些的视图只能查不能改。触发器里 INSERT 只有 NEW、DELETE 只有 OLD、UPDATE 两者都有。

6范式判定流程 ★

  1. 求候选码：把属性分四类——只在左（L）、只在右（R）、两边都有（LR）、都不出现（N）。若 (L∪N)⁺ = U，则 L∪N 是唯一候选码；否则在 LR 中逐个（或组合）求闭包，闭包 = U 即为候选码。
  2. 标主属性：出现在任一候选码中的属性是主属性，其余是非主属性。
  3. 找函数依赖：主码 → 全部属性；再看有没有「非主属性依赖码的一部分」（部分依赖）、「非主属性依赖非主属性」（传递依赖）。
  4. 定级别：1NF → 消除非主属性对码的部分依赖得 2NF → 再消除传递依赖得 3NF → 每个决定因素都含码得 BCNF → 再消除非平凡多值依赖得 4NF。
表 5　各级范式的判定口径
范式一句话判据要消除的毛病
1NF每个分量不可再分表中有表
2NF不存在非主属性对码的部分函数依赖组合码里的「半截依赖」
3NF不存在非主属性对码的传递函数依赖非主属性决定非主属性
BCNF每个决定因素都包含码（主属性也不能传递依赖）主属性之间的依赖
4NF每个非平凡多值依赖 X→→Y 中 X 都包含码一个表里两套独立的多值事实

例题 · 判定 R(Sno,Sname,Sdept,Mname,Cno,Grade)

F = {Sno→Sname, Sno→Sdept, Sdept→Mname, (Sno,Cno)→Grade}。

(Sno,Cno)⁺ = 全部属性，故码为 (Sno,Cno)，非主属性 Sname、Sdept、Mname、Grade。
Sname、Sdept 部分依赖于码（只依赖 Sno）→ 不是 2NF。
若强行分解为 R1(Sno,Sname,Sdept,Mname)、R2(Sno,Cno,Grade)：R1 中 Sdept→Mname 是传递依赖 → R1 只到 2NF，还不是 3NF。
再分解为 R11(Sno,Sname,Sdept)、R12(Sdept,Mname)：两者都是 BCNF，且分解无损、保持依赖。

口诀：一原子、二完全、三传递、BC 决定含码、四多值——判定时按这个顺序一项项排除。

7E-R 图转关系模式 ★

表 6　联系类型的转换规则
联系转换方法主码说明
1:1并入任一端，或单独建关系并入端的主码并入「参与少」的一端可减少空值
1:n并入 n 端，加 1 端主码作外码n 端原主码也可单独建关系（主码为 n 端主码）

易错

① m:n 联系不能合并进任何一端，否则产生大量冗余；② 1:1 并入端要选「全部参与」的一侧，避免外码为空；③ 转换后要标出主码与外码，题目要求「指出参照关系」时不能只画表。

8查询优化：规则与语法树 ★

代数优化的五条启发式规则

  1. 选择下推：把 σ 尽量移到叶子（先缩小关系）。
  2. 投影下推：只保留后续用到的列。
  3. 选择与笛卡尔积合并为连接（避免大中间结果）。
  4. 连接交换/结合：先做结果小的连接。
  5. 提取公共子表达式，一次计算多次使用。

物理优化的两条路线

  • 启发式规则：选择条件上有索引且选择率低 → 用索引扫描；连接表小 → 嵌套循环；已排序 → 排序合并；等值连接且内存够 → Hash Join。
  • 基于代价：用统计信息（元组数、块数、不同值个数、索引层数）估算 CPU + I/O 代价，选最小者。

考点 · 画树题的标准答法

① 写出初始语法树（σ、π、× 按 SQL 结构自上而下）；② 每一步说明用了哪条等价变换规则（如「选择对笛卡尔积分配，σ 下推」）；③ 画出优化后的树，标出连接顺序；④ 一句话说明代价变化（中间结果元组数从 X 降到 Y）。

表 8　三级封锁协议
协议加锁规则释放时机解决
一级修改前加 X 锁事务结束才释放丢失修改
二级一级 + 读前加 S 锁S 锁读完即放、X 锁到事务结束丢失修改 + 读脏数据
三级一级 + 读前加 S 锁S 锁也到事务结束才放丢失修改 + 脏读 + 不可重复读
  • 两段锁（2PL）：扩展阶段只加锁不释放，收缩阶段只释放不加锁。2PL 是可串行化的充分条件，不是必要条件；遵守 2PL 仍可能死锁。
  • 冲突可串行化：构造优先图，若图中无环则可串行化，拓扑序即等价串行顺序。冲突操作指不同事务对同一数据的「读-写」「写-读」「写-写」。
  • 活锁：先来先服务（FCFS）破解；死锁：预防用一次封锁法/顺序封锁法，诊断用超时法/等待图法（有环即死锁），解除靠回滚代价最小的事务。
  • 意向锁：IS、IX、SIX。给后代加锁前，先对祖先加相应意向锁；SIX = 对自身加 S、对后代加 X 的意向。
口诀：一级防丢、二级防脏、三级防重读；2PL 充分不必要；等待图有环必死锁。

10恢复：故障与动作对照 ★

表 9　三类故障的恢复策略
故障后果恢复动作执行者
事务内部故障事务未提交，数据库可能处于不一致状态UNDO 该事务（反向扫描日志、恢复前像）DBMS 自动
系统故障（断电、崩溃）内存丢失，未提交事务可能已写盘，已提交事务可能未写盘UNDO 未提交 + REDO 已提交DBMS 自动
介质故障磁盘损坏，数据库本身被破坏装入最近副本 + 用日志 REDO 已提交事务DBA 介入

考点 · 日志登记两条原则（必背）

  1. 先写日志，后写数据库（Write-Ahead Log）：保证 UNDO 时有前像可回滚。
  2. 事务提交前，其日志记录必须已写盘：保证已提交事务的 REDO 有据可依。

日志记录格式：事务标识、操作类型、操作对象、前像（旧值）、后像（新值）。日志是追加写，不能随意修改。

例题 · 检查点恢复

检查点时刻正在执行的事务为 {T2,T5}；此后日志中出现 T2 提交、T3 开始并提交、T4 开始未提交、T5 未提交。

从检查点正向扫描：ACTIVE-LIST={T2,T5} 先入 UNDO；遇到 T2 提交 → 移入 REDO；T3 新开始 → 入 UNDO，随后提交 → 移入 REDO；T4 入 UNDO 不提交；T5 不提交。
结果：REDO={T2,T3}，UNDO={T4,T5}。检查点之前的操作一律不用处理。

易错

① 系统故障必须既 UNDO 又 REDO，不能只 REDO；② 介质故障的 REDO 起点是「副本时刻」，不是检查点；③ 动态转储必须与日志配合才有意义；④ 「数据库镜像」用于提高可用性，不能替代备份。

11高频简答 18 条

  1. 数据库系统的特点：数据结构化；共享性高、冗余低、易扩充；独立性高；由 DBMS 统一管理和控制。
  2. 数据模型三要素：数据结构（静态）、数据操作（动态）、完整性约束（语义）。
  3. DBMS 的功能：数据定义、组织存储管理、操纵、事务与并发/恢复、建立与维护、其他（通信接口）。
  4. DBA 职责：决定内容与结构、模式设计、存储结构与存取策略、安全性与完整性、监控与调优、转储与恢复。
  5. 数据独立性：逻辑独立性靠外模式/模式映像；物理独立性靠模式/内模式映像。
  6. E-R 图三要素：实体（矩形）、属性（椭圆）、联系（菱形），联系上标 1:1/1:n/m:n。
  7. 视图的作用：简化查询、逻辑独立性、安全保护、多视角看数据、表达更清晰。
  8. 视图可更新的条件：单表、含主码、只含选择与投影，不含聚集/分组/DISTINCT/表达式列。
  9. SQL 特点：综合统一、高度非过程化、面向集合、同一种语法两种使用方式、语言简洁。
  10. 完整性 vs 安全性：完整性防「合法用户的无意错误」，安全性防「非法用户的恶意破坏」。
  11. DAC 与 MAC：DAC 由数据属主自主授权（GRANT），灵活但可能被绕过；MAC 由系统按密级强制（下读上写），更严格。
  12. 为什么用 2NF/3NF：消除冗余与插入/删除/更新异常；范式过高会增加连接开销，故可反规范化。
  13. 无损连接与保持依赖：分解后自然连接可还原原关系（无损）；分解后的依赖可由各子模式依赖推出（保持依赖）。3NF 分解可同时做到，BCNF 分解只能保证无损。
  14. 查询处理四阶段：查询分析 → 查询检查 → 查询优化 → 查询执行。
  15. 事务 ACID：原子性、一致性、隔离性、持续性（由日志与并发控制保证）。
  16. 并发三类不一致：丢失修改、不可重复读、读脏数据。
  17. 两段锁与可串行化：2PL 保证冲突可串行化（充分非必要）；遵守 2PL 可能死锁。
  18. 日志的作用：记录每次更新，支持 UNDO/REDO，是恢复的基础；必须遵守「先写日志」与「提交前写日志」两条原则。
